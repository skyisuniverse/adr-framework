# Templates

Currently [create-adr-app](https://github.com/skyisuniverse/create-adr-app) scaffolds the adr app file structure by copying the directory with pre-developed files from template directory into target directory.

However, the template folder doesn't actually contain templates - the copied files are just next.js files of a project developed earlier. 

What would be the best way to scaffold the project taking into account following considerations:

1. With current setup in order to maintain the latest version of dependencies (for a **consuming \*-adr-app** (and the **create-adr-app** itself))) there'd be a need to manually update those in the next.js project in the [create-adr-app//template](https://github.com/skyisuniverse/create-adr-app/tree/main/template) folder
and only then it'd be possible to get latest dependencies by scaffolding a new project.

What about **consuming \*-adr-app** projects that have already been scaffolded?

1.1. With  current setup with updating dependencies versions it could be time-consuming to manually update the codebase to the APIs of the updated dependencies (including API changes, breaking changes, etc).

One possible solution would be to include a cli command similar to **nx's migrate** and
**turborepos (???)** that programmatically updates the entire codebase according to the consuming dependencies' updates (including breaking changes(?)).

---

2. Development and releasing of new features and fixes should probably be done in the separate (main?) adr-app repo. All updates (new features and fixes) should be easily gettable in the consuming **\*-adr-app**.
